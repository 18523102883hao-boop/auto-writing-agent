# Harness工程：一个被大多数人忽略的独特视角

最近AI圈子里有个词火得一塌糊涂，跟OpenClaw差不多同期出圈。

如果你听过提示词工程、上下文工程，那你大概能猜到我说的是啥——Harness工程。

但我今天想聊的，不是Harness该怎么定义、怎么用。这些你去搜，能搜出一大堆教程。我想聊的是一个正在悄悄发生、但大部分人还没注意到的视角。

说实话，这个视角我也是在踩了一堆坑之后才意识到的。

先说说我踩的坑。

我做视频，最头疼的不是剪辑技术，是素材。

画面、音乐、音效、节奏……这些东西要凑齐，太花时间了。所以我就想着，能不能做个Bio生成器——根据我的讲稿，让AI自动调用生图、生视频、生音乐的模型，给我生成素材。

但我很快发现一个问题：大模型生成的提示词，非常不可靠。

而且更麻烦的是，生成的内容到底好不好，没法判断。没有反馈循环，我的Bio生成器就不是一个有效的Harness。

这时候我才意识到，我可能根本没搞懂Harness是啥。

Harness直译过来是"马具"。

你要让马拉车，需要的那些胸带、缰绳、鞍具，都是Harness。说白了，就是让马能更好完成工作的那些工具。

套用到AI上，道理是一样的：你要让一个AI Agent更好地完成工作，也需要Harness。

记住这个公式：**AI Agent = 模型 + Harness**。

模型是马，Harness是马具。除了模型本身，其他所有让AI能正常工作的软件环境、基础设施，都属于Harness。OpenClaw、Cloud Code，这些都是Harness。

但光知道定义还不够，你得理解Harness的核心原理：

**Harness是通过反馈循环，来解决大模型输出的概率性问题。**

啥意思呢？

AI调用工具，有时候会出错。这时候Harness就起作用了——它告诉AI"你调用错了"，然后AI修正、再调用。如果下次对了，这个反馈循环就是有效的。

一个好的Harness，能通过不断反馈，把AI输出的随机性给约束住。

打个比方，就像你教小孩骑自行车。

他在前面骑，你在后面扶着。他歪了，你喊"往左"；他偏了，你喊"往右"。这就是反馈循环。

没有你在后面扶着，他大概率摔个鼻青脸肿。

所以Anthropic、OpenAI、Cursor这些公司都在讨论，到底什么样的Harness才算有效。

从效果维度来分，大概有这么几个方向：让人类更少介入、让AI Agent能运行更久、让更多AI Agent能协作解决复杂问题。Andrej Karpathy也说过，好的Harness应该能用更少的token完成任务。

听起来都很合理对吧？

但问题就出在这里。

现在不管是国内还是国外，大家的眼光都聚焦在一件事上：**怎么用Harness解决软件工程的问题**。

怎么让AI写代码更靠谱、怎么让AI能自动修bug、怎么让AI能独立完成一个项目的开发。

但如果你要做一人公司，或者想成为超级个体，你的问题就只有软件工程吗？

我觉得不是。

直到我看到一篇论文，才打开思路。

这篇论文用了一个视觉多模态模型当裁判，给生成的图片打分。但不是简单给个分数，而是把AI生成的提示词和用户需求，拆解成很多个客观维度的判断问题。

比如我要生成一张"美短猫在午睡"的图片，它会生成一系列断言式提问：

- 猫咪是不是黑白相间的？
- 当前是不是中午？
- 猫咪是否在睡觉？

然后逐项打分。

我实测过，精度大概在几十毫秒左右。

对，你没听错，几十毫秒。这个精度足够用了。

这样一来，图片有没有达到要求，就被量化了。

再加上一套搜索算法，通过不断调整提示词、重复打分、记录历史轨迹，AI就能从过去的失败中学习，找到控制图片效果的关键词。

我的Bio生成器，终于从一个"抽风"的系统，变成了一个能用的工具。

这件事让我意识到：

**Harness不仅可以用于约束大语言模型，也可以用于控制多模态输出的质量。**

这和Ian Goodfellow博客里提到的对抗网络是一个逻辑：一个生成，一个判别，在对抗中迭代。

只不过这里生成的是图片，判别用的不是软件工具，而是另一个AI模型。

这时候我才发现，之前可能陷入了一种思维定式。

大家都在讨论用Harness解决软件工程的问题，但如果给Harness的目标再加一个维度——让它去控制多模态模型的输出质量——视野是不是一下就打开了？

说白了，我们不只是在训练AI写代码，我们还在训练AI"审美"。

我们可以用算法加多模态模型，来检查视频、图像、音频，甚至连音频里的情绪都可以评估。

让模型的输出更符合我们的要求。甚至可以用复杂的多模态模型编排，来实现更复杂的内容生产。

巧的是，我很快就找到了一个例子。

前阵子刚出的一篇论文叫CardClaw，它是一个视频加音频的剪辑工具。不是某个单一文本模型的能力，而是六个组件、用了四种模型来组合编排。

先用Whisper识别字幕，然后用算法做镜头切割，用Gemini Pro做编辑，用千问Omni理解音乐，用Minimax做精准裁切，最后用千问VL从三个维度审查。

六个组件，四种模型，就为了剪个视频。

听起来很夸张对吧？但这正是Harness的价值所在。

除此之外，我还发现不少论文都有类似的线索。

它们没有大肆使用Harness这个热词，而是非常务实地用各种多模态模型，实现了复杂的编排。

这些论文没上热搜，但里面的思路，可能比那些刷屏的"AI取代程序员"更有价值。

说到这里，我想借用英伟达官网对MLM（多模态模型）的定义来做个总结：

**这个世界是多模态的，所以和人类交互的数字内容，也不应该仅限于文本。**

说白了，我们生活在三维世界里，不是活在代码编辑器里。

所以在讨论Harness工程的时候，希望大家打开视野。

不要只盯着代码和软件，别忘了还有那么多生图、生视频、生音乐的模型。它们同样需要Harness，同样需要反馈循环来约束输出的随机性。

写代码很重要，但写代码只是AI能力的冰山一角。

对于想做一人公司的人来说，这意味着什么？

意味着你的AI工具箱可以更丰富。

不只是让AI帮你写代码，还可以让AI帮你生成视频素材、帮你检查生成内容的质量、帮你自动化剪辑流程。这些都不是靠一个模型能搞定的，而是需要多个模型组合、需要Harness来 orchestrate。

技术洞察力很重要。

看到新模型发布的时候，脑子里要有一张地图：这个模型是干什么的？它能解决什么问题？我以前想实现但实现不了的场景，现在是不是可以搞定了？

这种直觉，比任何单一工具都值钱。

最后说两句。

我知道很多人现在对AI有点审美疲劳，觉得又是新词又是新概念的，烦不烦。

但Harness这个概念，我觉得值得认真看看。不是因为它火，而是因为它解决了一个真问题：怎么让AI的输出从"抽风"变成"可控"。

而当你把视野从代码扩展到图片、视频、音频的时候，你会发现，真问题其实比想象中多得多。
