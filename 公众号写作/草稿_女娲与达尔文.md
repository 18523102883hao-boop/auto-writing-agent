## 女娲.skill：让乔布斯、马斯克给你打工

花叔开源的「女娲.skill」，一周斩获8000+ Star。

口号很直接：**你想蒸馏的下一个员工，何必是同事。**

女娲能蒸馏任何人的思维方式——乔布斯的产品哲学、马斯克的第一性原理、芒格的多元思维模型、Naval的人生杠杆理论。输入一个名字，系统自动完成调研、提炼、验证。

### 这不是角色扮演

很多人第一反应是：这不就是AI角色扮演吗？

不是。

角色扮演是复读名人语录。女娲提取的是**认知操作系统**。

来看一个真实对话：

**用户**：OpenAI和Anthropic谁的方向是对的？

**乔布斯（蒸馏版）**：
> 你问错了。这不是一场关于方向的竞赛。这是一场关于品味的竞赛。
>
> OpenAI像1985年的微软。什么都做，什么都要赢。这种策略能赢市场份额。问题是——当你什么都做的时候，你不可能每件事都做到insanely great。
>
> Anthropic更像早期的Apple。聚焦。Focus means saying no to a hundred good ideas.
>
> 但两家公司都犯了一个我绝对不会犯的错误——他们不控制硬件。
>
> 最终赢的可能是同时控制芯片、模型和用户界面的人。你知道现在谁在同时做这三件事吗？Apple.

这段话里没有一句是乔布斯的原话。但它用了乔布斯的**心智模型**：聚焦即说不、端到端控制、品味至上。

再看Naval：

**用户**：我同时想做自媒体、写书、做独立开发，精力完全不够。

**Naval（蒸馏版）**：
> 你列了三个欲望。每个欲望都是你跟不快乐签的一份合同。不是精力不够，是合同太多。
>
> 问你自己：哪一个做起来你会忘记时间？那个就是你的特定知识所在。
>
> 不是三选一。是先一，再一，再一。串行复利，不是并行内耗。

这是Naval的**「欲望即合同」框架**——不是简单的励志语录，而是一套可以指导决策的认知工具。

## 达尔文.skill：让Skill自己进化

女娲负责**造**Skill。但造出来的Skill，质量参差不齐怎么办？

这时候就需要「达尔文.skill」。

受Karpathy autoresearch启发，达尔文用**自主实验循环**批量优化所有Skill。核心机制很简单：

1. **8维度评估**——结构质量 + 实际效果
2. **棘轮机制**——只保留改进，自动回滚退步
3. **独立子agent评分**——避免"自己改自己评"的偏差

### 为什么需要达尔文？

Claude Code的Skill生态在快速扩张。当你有10个Skills时可以手动维护；当你有60+个Skills时，你需要一个系统。

传统的Skill审查是纯结构性的：检查格式对不对、步骤有没有编号、路径能不能访问。但一个格式完美的Skill，跑出来的效果可能很差。

达尔文同时评估**结构质量**和**实际效果**，然后只保留真正有改进的修改。

### 棘轮机制：时间站在你这边

达尔文的核心理念是：**只保留改进，时间就站在你这边。**

具体流程：

1. 找出得分最低的维度
2. 针对该维度生成1个具体改进方案
3. 编辑SKILL.md，git commit
4. 子agent独立重新评分
5. 新分 > 旧分 → 保留；否则 → git revert

分数只能上升。每一轮要么改进Skill，要么干净地回滚。不会随时间积累局部退化。

```
轮次1: 72分 → 保留
轮次2: 75分 → 保留（当前最优）
轮次3: 73分 → 回滚（低于75）
轮次4: 78分 → 保留（新最优）
```

安装同样简单：

```bash
npx skills add alchaincyf/darwin-skill
```

然后说「优化所有skills」或「优化某个skill」就行。

## 女娲 + 达尔文：造Skill + 进化Skill

这两个项目的关系很清晰：

- **女娲**负责从0到1——把一个人的思维方式蒸馏成可运行的Skill
- **达尔文**负责从1到N——让这个Skill持续进化，质量只升不降

女娲的Phase 5双Agent精炼，就内置了达尔文的评估体系。这也是为什么女娲生成的Skill质量高的原因之一。
