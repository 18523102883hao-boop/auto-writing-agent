自动化写作 Agent 构建实战：从 0 到 1 打造公众号内容生产流水线

上周三凌晨 1 点，我坐在电脑前，看着屏幕上闪烁的光标，突然意识到一个问题：我们每天都在写公众号文章，但为什么每次都要从头开始？

选题、搜索资料、写作、配图、排版、发布……这套流程我们已经重复了上百遍。能不能让 AI 帮我们 automate 掉那些重复的部分，让我们专注于真正重要的内容创作？

这就是我们构建自动化写作 Agent 的起点。

为什么是公众号写作？

你可能会问，市面上已经有那么多写作工具了，为什么还要自己搞一个？

原因很简单：现有的工具都不够懂我们​。

它们要么只是简单的模板套用，要么就是纯粹的 AI 生成，缺少了一个关键环节——流程化​。

我们需要的不是一个"一键生成文章"的黑盒，而是一个能够理解我们写作流程、能够在每个环节提供辅助、能够保证内容质量的智能助手。

所以，我们决定自己动手。

第一步：拆解写作流程

在开始写代码之前，我们花了整整两天时间，把公众号写作的完整流程拆解成了 12 个步骤：

Step 1-8：内容创作核心（人工主导）

理解需求 & 保存 Brief

信息搜索与知识管理

选题讨论

创建协作文档

学习风格

等待测试数据

创作初稿

三遍审校

Step 9-12：发布流程自动化（AI 增强）

9. 文章配图

10. 封面图生成

11. 排版

12. 发布

这个拆解非常关键。我们发现，Step 1-8 是内容质量的核心，必须人工主导​；而Step 9-12 是重复性劳动，可以交给 AI​。

这个认知直接决定了我们的技术路线：不是用 AI 替代写作，而是用 AI 增强写作​。

技术选型：为什么是 baoyu skills？

在技术实现上，我们面临几个选择：

方案 A：全部自己写

优点：完全可控

缺点：工作量大，需要处理图片生成、浏览器自动化等复杂逻辑

方案 B：使用现有 API

优点：快速集成

缺点：依赖第三方，定制性差

方案 C：baoyu skills + 自定义脚本

优点：平衡灵活性和开发效率

缺点：需要学习新工具

我们最终选择了方案 C。

baoyu 是一套开源的自动化工具集，包含了文章配图、封面图生成、公众号发布等功能。它的优势在于：

基于 DashScope（通义万相）API，图片质量有保障

命令行调用，容易集成到现有流程

开源可定制，可以根据需求修改

当然，我们也自己写了一些补充脚本，比如浏览器自动化排版（使用 Playwright 操作 editor.huasheng.ai）。

实战：生成一张封面图

理论说了这么多，来看实际效果。

这是我们在测试时生成的一张封面图：

node scripts/baoyu-cover-image.js \

--title "自动化写作 Agent 构建实战" \

--style tech \

--output test-cover.png

执行后，脚本会：

调用 DashScope API，提交图片生成任务

轮询获取生成结果（约 10-30 秒）

下载图片到本地

费用方面，通义万相的定价是约 ¥0.12/张，一次测试下来，生成 4-6 张配图 + 1 张封面，总费用不到 1 块钱。

踩过的坑

整个开发过程当然不是一帆风顺。分享几个我们踩过的坑：

坑 1：一开始想重构整个流程

最开始，我们犯了一个错误：想用一个全新的 8 步流程替代原有的 9 步写作流程。

结果发现，这样会破坏原有的内容质量保证机制。后来我们及时调整，改为在原有流程基础上增加自动化增强​，而不是替换。

这个教训很深刻：工具是为人服务的，不应该让人去适应工具​。

坑 2：浏览器自动化的坑

Step 11 的排版自动化，我们最初想用 Selenium，后来发现 Playwright 更轻量、更稳定。

但即使如此，还是遇到了页面结构变化导致选择器失效的问题。最终的解决方案是：提供手动备选方案​，自动化失败时可以手动操作。

坑 3：API 调用的坑

DashScope API 的异步任务处理需要轮询，一开始我们没有处理好超时情况，导致某些任务卡死。后来增加了 30 次轮询上限和错误重试机制，才解决了这个问题。

成果：现在的自动化写作 Agent

经过几轮迭代，现在的自动化写作 Agent 已经可以完成以下工作：

自动化的部分：

✅ 根据文章内容生成配图（4-6 张）

✅ 生成封面图（支持多种风格）

✅ 浏览器自动化排版

✅ 生成公众号发布格式

人工主导的部分：

✅ 选题讨论

✅ 内容创作

✅ 三遍审校

✅ 最终发布确认

这个分工是合理的：AI 做它擅长的（重复性劳动），人做人擅长的（创意和判断）​。

下一步：扩展到小红书、抖音

公众号写作只是第一步。接下来，我们计划把这套流程扩展到：

小红书​：图文种草笔记自动化

抖音​：短视频脚本自动化

视频号​：直播脚本自动化

每个平台的调性和格式不同，但核心的写作流程是相通的。我们只需要针对不同平台做适配，就可以复用大部分代码。

最后的思考

这次自动化写作 Agent 的构建，让我们对"AI 增强工作流"有了更深的理解：

流程优先​：先拆解流程，再考虑自动化，不要本末倒置

人机协作​：AI 不是替代人，而是增强人

质量第一​：自动化不能以牺牲质量为代价

持续迭代​：第一版肯定不完美，但要能快速迭代

回到最初的问题：我们每天都在写公众号文章，为什么每次都要从头开始？

现在，我们有了答案：因为重要的事情，值得用正确的方式重复做​。

而 AI，就是帮我们找到那个"正确的方式"的工具。
